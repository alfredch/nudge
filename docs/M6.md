## Lokal geprüft (2026-10-31)

- `cargo clippy -D warnings`, Tests unter `dbus-run-session`: Die D-Bus-Tests laufen dort wirklich, statt übersprungen zu werden.
- Release-Schritte im Container `ubuntu:22.04` (x86_64): Das .deb hat `Depends: libasound2 (>= 1.1.0), libc6 (>= 2.34)`, das höchste GLIBC-Symbol ist 2.34. aarch64 lässt sich erst in der CI prüfen.
- PKGBUILD im Container `archlinux:latest` mit `makepkg`: Bau, Tests, Installation und `nudge --version` klappen, namcap ist sauber bis auf eine harmlose Warnung zu `ld-linux`. Gefunden und behoben: Die LTO von makepkg bricht das Linken von aws-lc, deshalb `options=('!lto')`.
- Die Arch-Wiki-Seite zu Rust-Paketen war nicht abrufbar (Bot-Schutz). Das PKGBUILD folgt dem bekannten Muster (`RUSTUP_TOOLCHAIN=stable`, `cargo fetch --locked`, `--frozen`) und ist durch den Container-Bau abgesichert.
- Nicht geprüft: die Workflows selbst. Das geht erst, wenn das Repo existiert.

## Manueller Test (lokal gebautes .deb)

1. Installieren: `sudo apt install ./target/debian/nudge_0.1.0-1_amd64.deb`, dann `nudge --version`.
2. Umstieg auf den Paket-Service: `nudge install-service` ausführen, mit `/usr/bin/nudge`, also ohne `./target/debug/` davor. Erwartet: `Removed the previous …/nudge.service` und `Using /usr/lib/systemd/user/nudge.service`. Dann `systemctl --user status nudge`: geladen aus `/usr/lib/systemd/user/nudge.service`, enabled, active, Main PID zeigt `/usr/bin/nudge daemon`.
3. Icons: Das Tray zeigt die eigene Glocke. Bei „Pause“ ist sie durchgestrichen, bei einem Notfall erscheint ein roter Punkt.
4. GNOME: Bei Einstellungen → Benachrichtigungen prüfen, ob „Nudge“ mit Icon aufgeführt ist. Die Notifications zeigen „Nudge“ und das App-Icon.
5. Ruhezeiten-Kontrolle: Der neue `desktop-entry`-Hint könnte ändern, wie GNOME Banner behandelt. Den M4-Schritt 6 (Ruhezeiten, Priorität 0 still) einmal wiederholen.
