# M3 – Robustheit

## Umsetzung

| Modul | Inhalt |
|---|---|
| `backoff.rs` | Exponentiell 5 s → 10 → 20 → … → max. 300 s, ±20 % Jitter. Reset, wenn eine Verbindung ≥ 60 s hielt oder ein Wake-Ereignis kam. |
| `wake.rs` | System-Bus, best effort, zwei voneinander unabhängige Watcher: logind `PrepareForSleep(false)` (Resume) und NetworkManager `PropertiesChanged` → neue `PrimaryConnection` (online gehen *und* Wechsel WLAN ↔ Ethernet ohne Unterbrechung). Die Ereignisse laufen über einen `watch`-Kanal, Bursts fallen dadurch zusammen. Fehlt ein Dienst, steht das im Log auf Info-Ebene, der andere Watcher läuft weiter. |
| `instance.rs` | Belegt `io.github.alfredch.Nudge` auf dem Session-Bus (`DoNotQueue`). Ein zweiter Daemon bricht mit Exit-Code 69 ab. Wird in M5 zur D-Bus-Schnittstelle für `status`/`pause` ausgebaut. |

## Verhalten im Daemon

- Ein Wake-Ereignis während einer Verbindung schließt sie und verbindet sofort neu (mit Abruf). Während der Wartezeit vor einem Neuverbinden bricht es die Wartezeit ab.
- Ereignisse vor einem Verbindungsversuch werden verworfen, denn der Abruf nach dem Verbinden deckt sie ab.
- Verbindungsaufbau (TCP, TLS, WebSocket, Login) höchstens 20 s (`nudge_api::CONNECT_TIMEOUT`), das Schließen einer alten Verbindung höchstens 3 s. Ohne diese Grenzen kann ein Connect nach einem Netzwechsel minutenlang hängen, und in dieser Zeit greifen weder Backoff noch Wake-Ereignisse.
- Watchdog wie in M2: kein Keepalive innerhalb von 90 s → Neuverbinden mit Backoff.
- Wie bisher: `R` → 1 s, `E`/`A`/4xx → Exit 78 ohne Neuverbinden.

## Tests

- Unit: Backoff-Folge, Jitter-Grenzen, Reset. Mit pausierter tokio-Zeit: Ein Wake-Ereignis bricht die Wartezeit ab und setzt das Backoff zurück, ohne Watcher läuft die volle Wartezeit.
- Instanz: zwei Anmeldungen am Namen, die zweite schlägt fehl, nach dem Freigeben klappt sie wieder (wird ohne Session-Bus übersprungen).
- Manuell: Suspend/Resume, WLAN aus/an, zweiter Daemon.

## Exit-Codes (für die systemd-Unit in M5)

| Code | Bedeutung | Neustart sinnvoll? |
|---|---|---|
| 0 | SIGTERM oder Ctrl-C | – |
| 1 | unerwarteter Fehler | ja (`Restart=on-failure`) |
| 69 | anderer Daemon läuft bereits | nein |
| 78 | Login nötig (`E`, `A`, 4xx, keine Credentials) | nein |

In M5 also `RestartPreventExitStatus=69 78`.
