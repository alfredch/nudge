# M1 – API-Kern (`nudge-api`)

Ziel: Die Library ist vollständig und gegen Mocks getestet. Es gibt noch keinen Daemon und keine UI.

## Schritte

1. **Workspace umbauen**
   - Root-`Cargo.toml` als Workspace (`resolver = "3"`, `[workspace.package]` mit Edition, Lizenz und Repository, `[workspace.dependencies]`).
   - `crates/nudge-api` (lib) und `crates/nudge` (bin, vorerst nur clap-Gerüst mit `--version` und Pflichthinweis).
   - `rust-toolchain.toml`, `.gitignore` um `.idea/` ergänzen, `LICENSE-MIT`, `LICENSE-APACHE`, `CHANGELOG.md`.
   - `[workspace.lints]`: `clippy::unwrap_used = "deny"` (in Tests erlaubt), `unsafe_code = "forbid"`.

2. **Typen** (`types.rs`)
   - `Secret(String)`: Newtype mit maskiertem `Debug`/`Display` und `zeroize` beim Drop.
   - `DeviceId`, `DeviceName` (validierender Konstruktor), `Receipt`, `MessageId(u64)`.
   - `Message` mit allen Feldern. Optionale Felder als `Option<T>`, `html`/`acked` als bool über einen eigenen Deserializer (die API liefert 0/1), `priority` als `i8`, `date` als Unix-Timestamp (`i64`).
   - Fixtures in `tests/fixtures/*.json` (aus der Doku plus Randfälle: fehlender Titel, HTML, Emergency).

3. **HTTP-Client** (`client.rs`)
   - `Client::new(user_agent)` mit konfigurierbarer Base-URL (für wiremock).
   - `login`, `register_device`, `fetch_messages`, `delete_up_to`, `acknowledge`, `download_icon`, `download_sound`.
   - Antwortauswertung zentral: `status != 1` → `ApiError { errors, request }`, HTTP 412 → `TwoFactorRequired`, HTTP 4xx bei bestehender Session → `InvalidSecret` (Re-Login nötig).
   - Keine eingebaute Retry-Logik, Backoff ist Sache des Daemons (M3).

4. **Fehler** (`error.rs`): `thiserror`-Enum, ohne Secrets in den Meldungen.

5. **PushStream** (`stream.rs`)
   - `Frame::parse(&[u8]) -> Result<Frame>`: reine Funktion, umfassend unit-getestet.
   - `PushStream::connect(url, device_id, secret)` → `impl Stream<Item = Result<Frame>>`. Ping/Pong und Close werden behandelt.
   - Kein Reconnect und kein Watchdog in der Library: Sie liefert nur Frames bzw. das Verbindungsende. Watchdog und Backoff kommen im Supervisor in M3, damit die Library deterministisch testbar bleibt.

6. **Tests**
   - Unit: Frame-Parsing, Deserialisierung, Namensvalidierung, maskiertes `Debug`.
   - `wiremock`: Login ok, 412 → 2FA → ok, Registrierung mit `errors`, Fetch, Delete (Formularparameter prüfen), Ack, User-Agent-Header auf allen Requests.
   - Lokaler Test-WebSocket-Server (`tokio-tungstenite` auf `127.0.0.1:0`): Login-Frame prüfen, Sequenz `# ! R`, `E` und `A`, Verbindungsabbruch.

7. **Abschluss:** `cargo fmt`, `clippy -D warnings`, Tests grün, CHANGELOG-Eintrag, erster Commit auf `main`.

## Abhängigkeiten (nudge-api)

`tokio`, `reqwest` (`rustls-tls`, `json`, `form`, ohne Default-Features), `tokio-tungstenite` (`rustls-tls-webpki-roots`), `futures-util`, `serde`, `serde_json`, `thiserror`, `url`, `zeroize`. Dev-Abhängigkeiten: `wiremock`, `tokio` (macros, rt-multi-thread).

## Vor dem Start klären

- Ein echter Test-Login gegen Pushover registriert ein Open-Client-Gerät, und damit startet die 30-tägige Testphase. M1 kommt ohne aus und testet nur gegen Mocks.

## Umsetzung: Abweichungen vom Plan

- `PushStream` implementiert nicht das `Stream`-Trait. Stattdessen gibt es `next_frame() -> Result<Option<Frame>>`, `Ok(None)` heißt Verbindungsende. Der Watchdog (M3) legt `tokio::time::timeout` darum.
- `PushStream::connect` bekommt den User-Agent auch für den WebSocket-Handshake.
- Statt eines eigenen Fehlertyps `InvalidSecret` gibt es `Error::Api { http_status, errors, request }` und `Error::is_client_error()`. Die API-Doku legt nicht fest, mit welchem Status ein ungültiges Secret abgelehnt wird. Das wird in M2 am echten Server geprüft.
- `Frame::Unknown(u8)` für unbekannte Bytes, Whitespace wird ignoriert.
- `DeviceName::sanitized()` (für den Hostnamen-Default) und `ResourceName` (schützt Icon- und Sound-Namen in URL und Dateiname vor Path Traversal) sind zusätzlich dazugekommen.
- Abhängigkeiten: reqwest 0.13 braucht das Feature `query`. Als TLS-Provider ist nur aws-lc-rs aktiv.
- Der TLS-Handshake gegen `wss://client.pushover.net` ist noch nicht getestet (nur `ws://` lokal). Das kommt in M2 beim ersten echten Login.
- Bis auf `id` sind alle Felder von `Message` optional bzw. haben Defaults. `fetch_messages` dekodiert jede Meldung einzeln und liefert `Fetched { messages, malformed }`. Nicht dekodierbare Einträge kommen roh zurück, und `Fetched::highest_id()` berücksichtigt sie, damit eine kaputte Meldung die Warteschlange nicht blockiert.
- Statt `needs_ack()` gibt es `requires_persistent_display()` (Priorität ≥ 2 und nicht quittiert, unabhängig vom Receipt) und `can_acknowledge()` (Receipt vorhanden).
