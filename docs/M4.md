# M4 – Komfort

## Umsetzung

| Modul | Inhalt |
|---|---|
| `notify.rs` | Notifications direkt über zbus (`Notify`, `CloseNotification`). Dieselbe Verbindung empfängt `ActionInvoked` und `NotificationClosed`. Eine Tabelle Notification-ID → Ziel (Message-ID, Receipt, Link, Text) mit höchstens 256 Einträgen, dazu Receipt → Notification-ID für Wiederholungen. Buttons nur, wenn der Server `actions` kann. |
| `actions.rs` | Behandelt Klicks. **Acknowledge** ruft `acknowledge` auf, markiert den Receipt im Verlauf und schließt die Notification. Bei einem Fehler bleibt die Notification stehen, dazu eine Info-Meldung, aber kein automatischer Retry. **Open link** startet `xdg-open` (nur http/https; einer URL ohne Schema wie `example.org` wird `https://` vorangestellt). **Copy** übergibt den Text per stdin an `wl-copy` oder `xclip -selection clipboard`. |
| `cache.rs` | `~/.cache/nudge/{icons,sounds}/<name>.{png,mp3}`. Jede Datei wird nur einmal geladen und atomar geschrieben (`.part` und dann rename). Timeout 5 s, ein fehlgeschlagener Name wird 1 h lang nicht erneut angefragt. |
| `sound.rs` | rodio auf einem eigenen Thread mit einer Warteschlange von 4 Sounds. Das Gerät wird pro Sound geöffnet, die Länge ist auf 30 s begrenzt. `sound_for`: Sound der Meldung, sonst `sound.default`. Still bei Priorität < 0, bei `no`/`none` („None (silent)“) und `vi`/`vibrate` („Vibrate Only“), während der Ruhezeiten (Priorität ≤ 0) und wenn `sound.enabled = false` ist. |
| `config.rs` | TOML mit `deny_unknown_fields`, eine fehlende Datei bedeutet Defaults. Beim Start ist eine kaputte Datei ein Fehler. Bei `SIGHUP` wird neu geladen, eine kaputte Datei behält die alte Konfiguration. |
| `history.rs` | `mark_acked`, `is_acked`, `prune` (einmal täglich, nach `received_at`). `busy_timeout` 5 s, weil Daemon und Action-Handler gleichzeitig schreiben. |

## Verhalten

- Priorität 2, unquittiert: critical, resident, ohne Timeout, mit dem Button „Acknowledge“. Der Server wiederholt sie, indem er dieselbe Meldung (gleiche `id`) erneut ausliefert. nudge zeigt sie dann erneut, ersetzt dabei die bestehende Notification über den Receipt und spielt den Ton. Wurde der Receipt hier schon quittiert, landet sie nur im Verlauf („already acknowledged“).
- Quittiert wird nur über den Button, nie beim Schließen oder bei einem Timeout.
- Kommen in einem Abruf mehrere Wiederholungen desselben Receipts (z. B. nach Offline-Zeit), wird nur die neueste gezeigt.
- Lässt sich der Sound einer Meldung nicht laden (unbekannt, Download fehlgeschlagen), wird `sound.default` gespielt.
- Ruhezeiten (`quiet_hours`): Priorität -1 und 0 kommen mit Urgency low und ohne Ton. Erwartet unter GNOME: kein Banner, nur ein Eintrag in der Liste (wird mit Testschritt 6 geprüft).
- Benachrichtigungstöne des Servers werden mit `suppress-sound` unterdrückt, die Töne spielt nudge selbst.

## Abhängigkeiten

- Neu: rodio 0.23 (nur `playback` und `mp3`), jiff, toml. Entfernt: notify-rust.
- Build: `libasound2-dev` (Debian/Ubuntu) bzw. `alsa-lib` (Arch). Laufzeit: libasound2. Optional: `wl-clipboard` oder `xclip`.

## Manueller Test

Vorher den Daemon neu bauen und starten. Beenden immer mit Ctrl-C, nicht durch Schließen des Terminals: Das schickt SIGHUP, und das lädt jetzt nur die Konfiguration neu. Der Daemon liefe dann ohne Terminal weiter, und der nächste Start endet mit Exit 69. Im Log sollte `copying to the clipboard with …` stehen.
Unter Wayland bietet sich `sudo apt install wl-clipboard` an, sonst wird xclip genutzt.

1. **Sound und Icon:** Eine Meldung mit Priorität 0 aus einer App mit eigenem Icon schicken. Erwartet: Icon in der Notification und der Pushover-Ton.
2. **Eigener Sound:** Eine Meldung mit `sound=bike` schicken. Erwartet: der Bike-Ton. Danach liegt `~/.cache/nudge/sounds/bike.mp3` im Cache.
3. **Still:** Je eine Meldung mit `sound=none` und mit Priorität -1 schicken. Erwartet: kein Ton.
4. **Link und Kopieren:** Eine Meldung mit URL schicken. „Open link“ sollte den Browser öffnen. „Copy“ klicken und den Text irgendwo einfügen.
5. **Notfall:** Priorität 2 mit `retry=30` und `expire=120` schicken. Erwartet: resident, Ton, Button „Acknowledge“. Ohne Klick sollte nach 30 s eine Wiederholung kommen. Bitte festhalten, ob sie die alte Notification ersetzt oder als zweite erscheint, und ob im Log eine neue Message-ID steht. Danach „Acknowledge“ klicken: Die Notification verschwindet, im Log steht `message … acknowledged`, und auf pushover.net bzw. in der Sender-App ist die Meldung als quittiert markiert. Danach sollten keine Wiederholungen mehr kommen.
6. **Ruhezeiten:** In `~/.config/nudge/config.toml` die Ruhezeiten so setzen, dass jetzt Ruhezeit ist:
   ```toml
   [quiet_hours]
   enabled = true
   start = "00:00"
   end = "23:59"
   ```
   Dann `pkill -HUP -x nudge` (Log: `configuration reloaded`). Eine Meldung mit Priorität 0 schicken: Erwartet wird kein Ton und kein Banner, aber ein Eintrag in der Liste. Eine Meldung mit Priorität 1 schicken: Erwartet werden Ton und Banner.
7. **Kaputte Config:** Einen Tippfehler einbauen (`enabeld = true`) und SIGHUP schicken. Im Log sollte eine Warnung stehen, die alte Konfiguration bleibt aktiv.
